# Task UI Prototype

明确任务与范围 → 确定视觉方向 → 简报与基准页 → 扩展原型 → 验收交付。

## 按需读取

阶段 1 识别目标端与载体；阶段 2 读取对应参考，阶段 3 实现、阶段 4 验收时沿用，无需重复全文读取。遇到载体判断问题可提前查阅。

双端分别读取端侧规范。任务模式不决定风格；预设和案例可选用、改造或另提方向，不是固定三选一菜单。

## 1. 明确输入

- **任务与范围**：明确用户、主要动作、页面清单与各页任务；先从需求和项目提取，缺则问。必要信息与风格问题合并，每次最多 2–3 问，不重复确认已知项或擅自扩页。
- **设计起点**：延续产品时沿用其设计约束；全新设计或只借业务时，仅提取任务、字段与状态，不以旧视觉稿、主题或组件外观为依据。不能因为在已有仓库试跑就默认延续旧设计。
- **端与载体**：识别 PC/移动/双端，以及手机网页、小程序或 iOS/Android App。优先从需求推导；仅说“移动端”且无平台线索时，默认手机网页并声明。影响核心流程且无法推导的载体问题须问；平板、横屏不自动纳入。
- **素材与数据**：优先使用授权范围内的业务字段、状态与资产；缺失项取合理默认并记入简报，品牌缺失记“无”。全新设计不继承旧品牌资产。小程序/App 仍交付网页原型，区分宿主示意与实际能力。

## 2. 确定方向

### 识别倾向

先读当次参考、倾向和禁用方向，再按 [偏好记忆](preference-memory.md) 读取同一使用者的相关记录；延续产品时再读现有设计系统/相邻页面。当次需求优先于历史偏好。历史选择可帮助推荐，不能自动当作本次选定或决策委托。

尚无方向信息时，用宿主问答工具问一次（无工具则直接提问）：“这次有没有希望采用的视觉方向？” 提供沿用现有、有大致倾向、暂无偏好等选项，允许自由描述。已有回答或委托则不重复问；明确跳过或工具返回无答案可按尚无偏好处理，仍待回复不算答案。

| 情况 | 下一步 |
|---|---|
| 明确方向：参考图、设计系统或具体描述 | 写简报并做基准页，不强制比较 |
| 模糊倾向或无偏好 | 做同题方向稿，等待用户选择或明确委托 |
| 明确委托：“风格你来定，直接做” | Agent 选定方向，写简报并做基准页 |

**无偏好不等于委托。** 方向确定后无需再确认简报；仅范围变化或方向被推翻时重问。

### 需要比较时：同一代表页的方向稿

1. 从范围内选能体现核心内容、密度和操作的代表页，默认做 2–3 个轻量可运行方向稿；不为省事只选简单首页。
2. 保持内容、数据、披露层级、操作能力与视口一致。用**字排、构图、边界/材质、色彩、图标/控件语言**说明主张；每两稿至少在两个非色彩维度上有可辨差异，包含字排或构图。只换色、图片比例、单双列、搜索位置或密度不算不同风格。
3. 提供一个可切换全部方向的 URL、源码与启动方式，每稿说明任务适配原因和主要取舍。切换器避让内容与操作区，截图不能替代网页。
4. 实际访问、切换并截图自查；同画布、同滚动位置比较全部方向稿，忽略配色和名称后仍应辨认字排、容器与构图。差异不足则合并为布局变体，另提视觉语言；无工具时声明未验证项并提供人工预览方式。
5. 用户可选择、混搭或全否决。混搭先统一视觉规则，全否决要给可见的新方向。按 [偏好记忆](preference-memory.md) 记录反馈及范围，推断须标注；审美选择不等于操作验证。

### 方向确定后：简报与基准页

先成文简报，再做代表页基准，随后扩展其他页面；可复用方向稿代码，但各页布局与密度须服务其任务。简报包含：

- **主张与依据**：具体视觉手法及其任务、品牌或偏好依据。
- **信息组织**：首屏焦点、层级、导航、分区与密度。
- **端侧决策**：载体、视口、返回、主操作、长内容与输入处理；双端的共用与重排；涉及宿主能力时说明模拟边界。
- **具体取值**：字体、色值、间距与组件规则；强调色、通用状态色、领域指标色分工。
- **假设与借鉴**：数据/素材默认值，借用手法及当次调整。

## 3. 扩展原型

- 补齐确认的页面、主要路径和所需状态，不扩成全功能产品。移动端重排信息与操作，保留业务含义、状态、输入及返回上下文。
- 独立原型采用最简单的本地运行方式；融入现有应用时沿用其技术栈。样式遵守基准，不随意加入字体、颜色与组件规则。
- 数据与文案业务自洽，模拟内容标为演示；素材优先已有授权资源，占位/示意图说明用途，不用整页 UI 位图冒充网页。
- 转正时移除方向比较工具和探索说明。

## 4. 验收（必须）

- PC 默认检查 1440×900、1280×800；移动端按 [移动参考 §7](mobile-design-reference.md#7-验收与证据边界) 的视口与矩阵。用户指定优先，双端分别验收。
- 确认内容加载完成、动画未隐藏元素；对照简报检查实际截图的焦点、层级、字排、对齐、溢出、颜色和相关空/加载/错误状态。主操作按任务时机可发现、可达，不为首屏露出强加固定栏。
- 实际走主要操作路径，检查反馈、状态保留与返回；截图不能替代点击。至少一轮审查，影响主要任务或可读可点的问题须修复并复验，无问题不反复改。
- 工具或范围无法覆盖的项列为未验证，剩余问题标“验收未完全通过”。区分浏览器尺寸、触控模拟、真机与宿主证据；无截图能力须标“未经视觉验收”，不得以文件生成替代验收。

## 5. 交付

提供原型源码、启动命令与运行地址、简报、验收结果及未验证项。截图附件可选，验收仍按阶段 4 执行。

任一阶段收到明确偏好、纠正或遗忘要求时，按 [偏好记忆](preference-memory.md) 更新；写入后简短告知变化。没有新证据则不更新，不把个人倾向改成通用规范或预设默认值。
