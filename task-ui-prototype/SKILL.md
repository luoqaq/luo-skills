# Task UI Prototype

明确任务与范围 → 确定视觉方向 → 简报与基准页 → 扩展原型 → 验收交付。营销或静态艺术任务应说明不适用。

## 按需读取

- 设计与验收：PC 读 [pc-design-reference.md](pc-design-reference.md)；移动端读 [mobile-design-reference.md](mobile-design-reference.md)，双端都读。移动规范未编写时须在简报声明，按通用流程执行。
- 梳理操作路径时读 [task-patterns.md](task-patterns.md)；任务模式不决定视觉风格。
- 先分析任务并形成初步主张，需要具体手法参考时才读 [visual-examples.md](visual-examples.md)。案例不是通用分类或默认三选一菜单，不要求标注“库内/库外”。

## 1. 明确输入

必须明确**用户及主要动作、交付页面清单与各页任务**。先从需求和项目提取，缺则问；与风格问题合并，每次最多 2-3 问，不重复确认已知信息或擅自扩充范围。

字段、图表、状态、示例内容、品牌资产和画布尺寸优先沿用项目；缺失时取合理默认并写入简报，品牌缺失记“无”，画布默认值见阶段 4。

## 2. 确定方向

### 识别倾向

先读用户参考、倾向、禁用方向及现有设计系统/相邻页面；当次需求优先于历史偏好，无记录不杜撰。已有方向、倾向、无偏好回答或决策委托时不重复问。

否则用宿主可用的问答工具问一次（无工具则正常提问）：“这次界面有没有希望沿用的视觉方向？” 可选“沿用现有产品/设计系统”“有参考或大致倾向”“暂无，请根据任务提出方案”，允许自由描述，不要求设计术语。

用户明确跳过或工具返回无答案时按“尚无偏好”处理；仍待回复时，沉默不算答案。此问题可跳过，阶段 1 的必需信息不可缺。

| 情况 | 下一步 |
|---|---|
| 明确方向：参考图、设计系统或具体描述 | 沿用约束，写简报并做基准页，不强制比较 |
| 模糊倾向：如“简洁”“科技感” | 转成具体视觉手法，做方向稿验证理解 |
| 无偏好或尚未提供 | 根据任务与内容设计方向稿供选 |
| 明确委托：“风格你来定，直接做” | Agent 在已有约束内选定方向，写简报并做基准页 |

**无偏好不等于委托。** 模糊/无偏好分支须等用户选方向或明确委托后才能扩展全部页面；委托不豁免范围与验收要求。

### 需要比较时：同一代表页的方向稿

1. 分析用户动作、页面职责、内容、品牌、平台和已知偏好，提出有依据的方向；不按行业或任务名称直接套风格。
2. 从已确认范围选一个能体现核心内容、密度和操作的代表页，避免只选简单首页。默认做 2-3 个轻量、可运行网页，聚焦一屏内容，交互仅够展示方向。
3. 各稿使用相同内容、数据和视口；可调整排序与权重，不删内容制造差异。字排、构图、阅读节奏须有明显区别，仅换颜色不算。
4. 交付**一个可切换全部方向的 URL**、源码与启动方式，每稿附“设计主张、任务适配原因、主要取舍”。文字/截图辅助，不能替代网页；切换器须避让内容，移动端兼顾安全区与底部操作区。
5. 检查实际访问与切换；有截图能力则截图自查渲染、溢出和遮挡，附件可选。缺少相应工具时声明未验证项并给人工预览方式，不以文件生成代替验收。
6. 用户可选定、混搭或全否决。混搭须统一视觉规则；全否决须给实际可见的新方向，不以原稿微调重交。局部喜好反馈可选；记录选择事实，模型推断须标注，审美选择不等于操作验证。

### 方向确定后：简报与基准页

所有路径均先成文简报，再将范围内的代表页做成基准页，随后扩展其余页面。可复用方向稿代码、tokens 和组件；后续页面按任务调整布局/密度，保持视觉语言一致。

简报须包含：

- **主张与依据**：预期效果及具体手法，依据来自任务、品牌、既有设计系统或明确偏好；将“高级/科技感”等倾向转为可在画面核对的规则。
- **信息组织**：首屏焦点、主次层级、导航与分区、各区密度及理由。
- **具体取值**：字体角色与字号阶梯、层级手法、色值/间距；强调色、通用状态色和领域指标色分工。
- **假设与借鉴**：输入默认值；若参考案例，说明借用手法及当次调整。

方向已确定后，展示简报即可继续，不再等待一次确认；仅范围变化或方向被推翻时重新询问。

## 3. 扩展原型

- 按基准页补齐已确认页面、主要交互和所需状态，交付可点击网页；不扩成全功能产品。
- 独立 HTML/CSS/JS 单文件优先，已有项目沿用技术栈；样式遵守简报，不随意加入新字体、颜色或间距。
- 文案与数据业务自洽；模拟数据标为演示，禁用 lorem ipsum、Test User 和无意义占位数字。
- 素材优先已有真实素材、授权素材；占位服务/简单 CSS 图形须说明用途，不得以生成的整页 UI 位图冒充网页。
- 转正时清理标题、注释和页面中的方向稿说明。

## 4. 验收（必须）

- 默认视口：PC 1440×900、1280×800；移动端按参考规范，未编写时 390×844。用户指定覆盖默认值。
- 确认截图非空白、内容加载完成、动画未隐藏元素；对照简报检查焦点、层级、密度、字排、对齐、截断、溢出、颜色、所需空/加载/错误状态，以及默认视口内主操作可见且可达，并应用端侧参考中的否决项。
- 至少一轮审查。发现问题则批量修复、重拍；无问题不硬改。至多两轮，仍有问题标“验收未完全通过”并列明。
- 实际操作主要交互路径，截图不能替代点击验证。缺少浏览器/截图工具时明确“未经视觉验收”及未验证项，提供启动命令和人工预览地址。

## 5. 交付

提供源码、启动命令与地址、设计简报、验收结果及未验证项，注明是原型。最终截图附件可选，不免除阶段 4 的验收。
