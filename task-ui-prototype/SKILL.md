# Task UI Prototype

输入页面需求，交付可运行原型 + 截图。质量来自流程：契约拦住瞎做，简报拦住套路，截图验收拦住自嗨。

## 适用范围

触发：以完成任务为目的的界面型页面原型，PC 端或移动端均可——工作台、后台、dashboard、列表/详情、分析页、表单、设置、消息中心、个人中心、内容管理等。判断标准：页面的主要职责是让人完成操作或获取信息，而不是说服访客。

不适用，遇到应明确说明并给出理由：

- **营销落地页、品牌官网首页**：目标函数不同——落地页的杠杆是说服与转化（叙事节奏、视觉冲击、情绪表达），本 skill 的规范和验收清单全是任务效率导向，套用会产出"正确但平庸"的页面。后续可另设模式、配独立参考文件
- **静态艺术图**（海报、PNG/PDF 画布）：交付物不是可运行网页，没有 DOM 和交互，截图验收与点击验证无从谈起，应使用画布类工具

## 加载参考文件

先判断任务平台，再读对应参考文件（阶段 2 和阶段 4 需要其中的规范）：

- PC：读 `pc-design-reference.md`
- 移动端：读 `mobile-design-reference.md`。若其内容未编写，在设计简报中声明"移动端参考规范未编写"，按本流程通用部分执行
- 双端任务：两个都读

## 五阶段流程

阶段 1 和阶段 4 是硬门槛（必须/不得）；阶段 2、3、5 是默认行为（应当）。

### 阶段 1：输入契约（硬门槛）

动手前必须确定两项，缺则问（一次最多 2-3 个问题，只问事实，禁止问"要不要现代一点"这类抽象品味问题）：

- **页面任务**：服务谁、主要动作是什么（一个动词短语）
- **交付范围**：页面清单——本次交付哪几个页面、各自的任务。确认后不得自动扩充；后续小修不重复确认

以下信息优先从项目中提取（读已有设计系统、相邻页面、代码），提取不到就用合理默认值并在设计简报中声明，不作为提问理由：

- 必须出现的字段、图表、状态清单
- 示例内容（文案、数据量级）
- 品牌资产（logo、色、字体），没有则记录"无"
- 参考方向与禁用方向
- 目标画布尺寸，未指定按阶段 4 默认值

### 阶段 2：设计决策（简报先行）

- **用户已给明确视觉方向**（参考图、设计系统、具体描述）：沿用，直接写设计简报。
- **用户未给方向**：先产 2-3 个轻量视觉方向稿——单屏、真实内容、只表达布局/密度/配色，不做完整交互。多个方向必须**视觉语言级**不同（字排气质、构图、阅读节奏），仅换配色/密度参数不算数。方向稿必须提供单一入口：一个带切换器的对比页（或单文件内 toggle），用户在一个 URL 里切换所有方向，不得要求用户分别访问多个地址。截图供用户选择；宿主无截图工具时，直接给出对比页 URL 请用户人工查看选择，并在简报中注明"方向稿未经截图验收"。用户选定或要求杂交后，基于选定方向写完整简报。
- **基准页**：选定的方向稿打磨后作为本次任务其余页面的视觉基准，后续页面对照它保持视觉语言一致。

设计简报必须成文（它是阶段 4 验收的对照基准），包含：

- **设计主张**：一句能落到画面上的话（如"像一份持续更新的研究刊物：结论醒目，证据紧密"），并写明它体现在哪几个手法上（栏宽比例、尺度差、分隔与节奏等）。只有"紧凑、蓝色、14px"这类参数不算主张
- 信息层级：第一屏焦点是什么，次要信息如何退后
- 密度档位：紧凑 / 标准 / 疏朗，附选择理由（查参考文件的分档矩阵）
- 布局骨架：导航形式、分区结构
- 视觉方向：具体色值、字号阶梯
- 阶段 1 所有默认假设的声明

禁止使用"高级、科技感、极简、大气"这类形容词作为决策依据。每个选择的依据可以是任务、品牌、既有设计系统，或用户明确表达的审美偏好，四者居一即可；毫无依据的随意默认值不允许。简报成文并展示给用户后即可继续实现，不再额外停等确认；只有出现新的核心设计决策（范围变化、方向被推翻）时才重新询问。

### 阶段 3：原型实现

- 独立 HTML/CSS/JS 单文件优先；已有项目则按其技术栈
- 文案和数据业务自洽：禁止 lorem ipsum、占位数字、"Test User"；模拟数据须符合业务逻辑、内部一致，并标注为演示数据
- 交互只实现演示主要动作所需的部分，不做全功能
- 素材优先级：项目已有真实素材 > 授权素材库 > 占位服务或简单 CSS 图形（需说明其功能）；禁止用图像生成模型产出整页 UI 位图冒充页面
- 保真条款：只使用简报中定义的颜色、字体、间距，不引入简报之外的视觉样式

### 阶段 4：视觉验收（硬门槛）

- 使用可用的浏览器或截图工具。默认视口：桌面 1440×900 和 1280×800；移动端按参考文件（未编写时用 390×844）。用户指定画布则覆盖默认值
- 先验证截图有效性：视口非空白、内容已加载、动画未隐藏元素，再开始检查
- 逐项检查（以下是否决项，任一命中必须修改）：第一屏无明确焦点、密度与页面类型不匹配、字排阶梯混乱、对齐/截断/溢出、颜色与简报不一致、缺真实状态（空/加载/错误按需）、主要操作不可见
- 简报对照：简报承诺的焦点、层级、密度，在截图中逐条核对成立
- 至少完成一轮完整审查。发现问题必须修改并重拍；未发现问题则记录检查结果，不为满足流程制造无意义微调。一轮批量截图、一次批量修复，至多两轮后停止打磨；达到上限仍存在问题的，标记"验收未完全通过"，在交付中列出已知问题清单
- 截图不能替代点击验证：主要动作的交互路径实际操作一遍
- 宿主无浏览器/截图工具时：不得假装验收。交付中必须显式声明"未经视觉验收"，并给出人工预览方式（启动命令 + 访问地址）

### 阶段 5：交付

- 源文件路径和预览方式（命令 + 地址）
- 最终截图（各默认视口，或验收豁免声明）
- 设计简报及关键选择说明
- 未验证部分清单
- 明确提示：这是原型，不是生产实现
