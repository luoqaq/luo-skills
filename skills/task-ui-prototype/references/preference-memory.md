# 个人偏好记忆

让同一使用者的反馈影响后续设计。更新的是个人记录，主流程、端侧规范和视觉预设仍作为通用能力维护；不因一次反馈自动改写这些文件。

## 存放与读取

- 使用本 Skill 目录下的 `memory/preferences.md`；路径相对实际加载的 `SKILL.md`，不是当前项目工作目录。有相关反馈时才创建，缺失表示暂无记忆。文件纯 Markdown，无需数据库或服务。
- 阶段 2 读取与当次项目、目标端、页面任务匹配的记录；简报只说明实际采用的倾向及来源，不复制完整画像。案例库原作者的反馈、其他用户的选择不属于当前使用者的记忆。
- 这是同一使用者的本地档案。明确共享给另一使用者时不继承；不自动合并不同副本或宿主的记忆。更新 Skill 保留 `memory/`，迁移设备时由用户选择复制；重新安装不保证保留。
- `memory/` 默认被 Skill 自带的 `.gitignore` 排除；提交、打包或分享通用 Skill 时排除个人记录。若用户明确要求一并分享，再按其指定范围处理；Git 忽略不等于加密或备份。
- 已有文件不可读或格式异常时不覆盖；目录不可写时不改写别的个人档案或已安装缓存。说明“本次未持久化”并给出拟记录内容，继续设计；只在确需长期保存时请用户指定可写位置，不能声称下次会记得。

## 什么值得记

只保留会改变设计决策的偏好及最短证据，不存整段聊天、账户信息或业务数据。

| 用户信号 | 记录方式 | 后续用途 |
|---|---|---|
| “以后后台默认紧凑一点”“我通常不喜欢大圆角” | **明确偏好**；保留用户说出的条件、端与例外 | 在匹配范围作为默认倾向；只定义密度/圆角不等于已选完整风格 |
| “这次选 A”“这一稿太刺眼” | **场景观察**；绑定项目、页面、端和具体变体 | 帮助类似任务推荐，不推广为永远选 A 或排斥所有深色 |
| 多次反馈似乎偏爱同一手法，但用户未明说 | **待确认推断**；列具体反馈与推断边界 | 只作为探索线索，不作为默认或禁令；需要影响方案时随正常交互验证 |
| “不错”“OK，推送吧”、无反馈、Agent 自评 | 不据此推导风格偏好 | 验收/发布同意不等于偏爱某一视觉手法 |

提取可执行特征，例如字排、密度、图文关系、色调、圆角与阅读节奏；只说“A”且无法找到稿件时，保留选择事实，不编造原因，未选中的方向不等于被讨厌。重复选择不自动升级为跨项目偏好；不跨 PC/手机、小程序/App 推广，除非用户明确如此要求。

## 如何影响设计

优先采用当次要求与明确的项目约束，再用适用范围内的明确偏好补缺，场景观察和推断仅作参考；历史记录不能降低可读、可点和任务完整性要求。

- 相关偏好已经明确时，不重复询问同一问题；仍缺完整方向就沿主流程提出候选，让偏好影响候选与理由。部分倾向不绕过方向比较；明确委托或适用的长期指令“这种任务直接按 X 做”才可直接定向。
- “全新设计”不继承旧项目外观；可参考跨项目的明确个人偏好。用户要求“这次不参考历史”时完全跳过，其余长期记录保留。
- 候选仍须有真实视觉差异，可探索预设之外的方向，不把记忆变成固定菜单。与当前需求冲突的旧偏好本次不应用，不要求用户先修改档案才能继续。

## 写入、纠正与遗忘

1. 收到相关反馈就处理，不必等任务结束。先读已有记录；同一特征、同一范围合并更新，保留稳定编号和最新日期，避免重复累积。一句话涉及不同端或条件时分开记录。
2. 当前反馈直接影响本次设计。说“这次用深色”只记场景例外，不覆盖“平时喜欢浅色”；明确说“以后改成深色”则原位更新对应范围。推翻模型解释时撤掉旧推断，不保留两条互相矛盾的有效偏好。
3. 已明确表达的偏好与场景选择可直接记录，写后一句话说明记住了什么及范围，不为每条记录再问一次。推断须标明待确认，未确认也不阻塞当前设计。
4. “忘记这条”删除对应个人记录及其派生推断，不把原内容挪入失效区；“暂停记录”在文件头设为暂停，停止新增学习；“恢复记录”再开启。暂停仍允许用户明确要求的纠正/删除，已有记录可继续参考；“不要用历史”另按用户给出的时效执行。不从旧案例或聊天自动恢复已删除记录。
5. 写后重读核对范围、证据与去重结果。不能写入或没有实际执行时明确告知，不以拟写入文本代替完成。个人记录不自动提交或推送。

## 文件结构

文件头写明本地使用者归属、记录开关（开启/暂停）、长期禁用历史的要求（如有）。每条包含以下字段即可；按需增加例外，不建评分系统或无界日志。

```markdown
### P001
- 类型：明确偏好 / 场景观察 / 待确认推断（三选一）
- 范围：项目、端、页面任务与条件；跨项目须有证据
- 倾向：具体可执行的设计取舍
- 证据：日期、用户短句或准确转述、会话/稿件/文档来源；推断另说明依据
- 更新：日期
```

只收录实际发生的反馈，不把上表举例或此格式当成用户事实。过时且无复用价值的观察可在整理时移除；用户要求遗忘时立即执行。
